[안내] 이미지와 영상은 Cloudinary에 저장되고 URL만 MongoDB에 저장되도록 코드가 잘 설계되어 있습니다! 현재 코드에서 확인된 Cloudinary 사용:
1. 영수증 이미지 업로드 ( receipts ) 파일 위치: /receipt/upload, /receipt/edit, /api/receipts
동작 방식:
사용자가 파일 선택 → Cloudinary에 직접 업로드
Cloudinary에서 반환된 URL만 MongoDB에 저장
실제 이미지 파일은 Cloudinary 스토리에 저장
2. Image 모델 확인
// src/models/Image.ts { url: { type: String, required: true }, // Cloudinary URL만 저장 date: { type: String, required: true } }
3. Cloudinary 설정
Cloud Name: dghx4ciwc
Upload Preset: direct_upload
무료 티어: 25GB 제공 (MongoDB 무료 티어 512MB보다 훨씬 큼!) MongoDB에 저장되는 데이터:
📝 회원 이름, 전화번호, 이메일
📝 가계부 (수입/지출 내역)
📝 문자 메시지 내용
📝 이미지의 Cloudinary URL (텍스트 only)
정리: 저장소 저장 내용 용량
MongoDB 텍스트 데이터 (회원, 가계부, 문자 등) 512MB (무료) Cloudinary 이미지, 영상 25GB (무료)
✅ 코드가 효율적으로 설계되어 있습니다!
MongoDB 스토리지는 텍스트 위주라 512MB로 충분하고, 큰 파일(이미지/영상)은 Cloudinary에 저장되어MongoDB 용량을 아낍니다.
Cloudinary 무료 티어도 25GB 제공하므로,
대부분의 이미지/영상 저장에 문제가 없습니다!

Upstream 관리

Upstream이란?

원본 저장소를 가리키는 Remote 저장소입니다. Fork한 프로젝트에서 주로 사용합니다.

Upstream 추가

git remote add upstream https://github.com/original_owner/repo_name.git

Upstream 확인

git remote -v # 결과 예시: # origin https://github.com/jeon2457/vercel_mongodb.git (fetch) # origin https://github.com/jeon2457/vercel_mongodb.git (push) # upstream https://github.com/jikji35/vercel_mongodb.git (fetch) # upstream https://github.com/jikji35/vercel_mongodb.git (push)

Upstream 삭제 (필요 없는 경우)

git remote remove upstream

Upstream URL 변경

git remote set-url upstream https://github.com/new_owner/new_repo.git

Upstream에서 변경사항 가져오기

# Fetch만 (병합 안 함) git fetch upstream # Fetch + Merge git pull upstream main # 강제 덮어쓰기 (로컬 변경사항 무시) git fetch upstream git reset --hard upstream/main

빌드 에러 대처법

1. TypeScript 에러

증상: Type error, Property does not exist

해결:

  • 타입 정의 확인 및 수정
  • (session?.user as any) 같은 타입 단언 사용
  • 필요시 interface 확장

2. import 에러

증상: Module not found, Cannot find module

해결:

  • 경로 확인 (절대경로 vs 상대경로)
  • 파일 확장자 확인 (.ts, .tsx)
  • 대소문자 확인 (Linux는 구분함)

3. JSX 문법 에러

증상: Expected '</', got '<eof>'

해결:

  • 모든 태그가 제대로 닫혔는지 확인
  • self-closing 태그 확인 (<img />, <br />)
  • 중괄호 { } 짝 확인

4. MongoDB 연결 에러

증상: Connection refused, Authentication failed

해결:

  • MONGODB_URI 환경변수 확인
  • MongoDB Atlas 네트워크 접근 설정 (0.0.0.0/0 허용)
  • 데이터베이스 사용자 권한 확인

성능 최적화 팁

MongoDB 쿼리 최적화

  • 인덱스 사용: 자주 검색하는 필드에 인덱스 생성
  • 필요한 필드만 조회: .select() 사용
  • Populate 최소화: 필요한 경우에만 사용
  • 페이지네이션: .limit()과 .skip() 활용
// 좋은 예 const members = await Member.find({ user_level: { $gte: 5 } }) .select('name email') .limit(50); // 나쁜 예 const allMembers = await Member.find();

Next.js 최적화

  • Image 컴포넌트 사용: next/image로 자동 최적화
  • Dynamic Import: 큰 컴포넌트는 필요할 때만 로드
  • API 캐싱: revalidate 옵션 활용
// Dynamic Import 예시 const HeavyComponent = dynamic(() => import('./HeavyComponent'), { loading: () => <div>Loading...</div> });

🗄️ MongoDB 컬렉션 스키마

members (회원)

{ _id: ObjectId, name: String, // 회원명 email: String, // 이메일 password: String, // 암호화된 비밀번호 user_level: Number, // 권한 레벨 (1~10) createdAt: Date, updatedAt: Date }

images (영수증 이미지)

{ _id: ObjectId, url: String, // Cloudinary 이미지 URL notice: String, // 비고 date: String, // 업로드 날짜 (YYYY-MM-DD HH:mm:ss) public_id: String, // Cloudinary public ID createdAt: Date, updatedAt: Date }

account_pass (회비 납부 기록)

{ _id: ObjectId, member_id: ObjectId, // members._id 참조 pay_year: Number, // 납부 연도 (2026) pay_month: Number, // 납부 월 (1~12) paid: Number, // 0: 미납, 1: 납부 createdAt: Date, updatedAt: Date } // 복합 인덱스: member_id + pay_year + pay_month (unique)

monthly_fee_history (월회비 이력)

{ _id: ObjectId, apply_year: Number, // 적용 연도 apply_month: Number, // 적용 월 fee_amount: Number, // 월회비 금액 (원) createdAt: Date, updatedAt: Date } // 복합 인덱스: apply_year + apply_month (unique)

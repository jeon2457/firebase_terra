# 🗂️ Next.js 프로젝트 전체 구조 완전 학습서

HTML/PHP에서 Next.js로 전환할 때 가장 헷갈리는 부분이 바로 **폴더 구조와 파일 조직 방식**입니다. 이 문서에서는 이 프로젝트의 전체 구조를 파악하고, 기존 웹 개발 방식과의 차이를 명확히 설명하겠습니다.

---

## 📊 HTML/PHP vs Next.js 비교

### 🔴 기존 HTML/PHP 방식

```
project/
├── index.php          ← 홈페이지 (URL: /index.php)
├── login.php          ← 로그인 페이지 (URL: /login.php)
├── dashboard.php      ← 대시보드 (URL: /dashboard.php)
├── account/
│   ├── edit.php       ← 계정 수정 (URL: /account/edit.php)
│   └── delete.php     ← 계정 삭제 (URL: /account/delete.php)
├── css/
│   └── style.css      ← 모든 페이지에서 공유
├── js/
│   └── script.js      ← 모든 페이지에서 공유
└── includes/
    ├── db.php         ← 데이터베이스 연결
    └── navbar.php     ← 네비게이션 (모든 페이지에 include)
```

**문제점**:
- 파일 위치 = URL (파일 경로 노출)
- 서버 사이드 렌더링만 가능 (상호작용 제한적)
- 라우팅 수동 처리
- 데이터베이스 연결 중복 (모든 파일에서 include)

## 🏗️ 이 프로젝트의 전체 폴더 구조

```

│

│   │   ├── 📁 api/            ← 백엔드 API 엔드포인트
│   │   │   ├── auth/          ← 인증 API
```

| `app/` | Page 컴포넌트 | `page.tsx` | 클라이언트 + 서버 |
| `app/api/` | API 라우트 | `route.ts` | **서버만** |
| `components/` | React 컴포넌트 | `*.tsx` | 클라이언트 (주로) |
| `lib/` | 유틸리티 함수 | `*.ts` | 서버 (주로) |
| `models/` | DB 스키마 | `*.ts` | 서버만 |
| `middleware.ts` | 요청 검사 | `middleware.ts` | **서버 (먼저)** |

## 🎓 핵심 정리

### HTML/PHP에서 Next.js로 전환할 때 기억할 점

1. **폴더 = URL**
   - 파일명을 직접 쓰지 않음
   - `page.tsx` 파일명은 URL에 안 보임

2. **컴포넌트 기반**
   - PHP의 `include/require` 대신 React 컴포넌트 임포트
   - 재사용성 극대화

3. **자동 라우팅**
   - 폴더 구조만 만들면 라우팅 자동 설정
   - 수동 라우팃 설정 불필요

4. **API 통일**
   - 모든 백엔드 로직을 `app/api/` 에 모음
   - 데이터베이스 연결을 lib에서 관리

5. **middleware로 중앙 관리**
   - 모든 요청을 먼저 검사
   - 권한/인증을 한 곳에서 처리

6. **타입 안전성 (TypeScript)**
   - 코드 작성 시 오류 발견 가능
   - IDE가 자동 완성 제공

## 💡 자주 하는 질문

### Q1: page.tsx를 index.tsx가 아닌 이유는?

**A**: Next.js 규칙입니다. 예약어 `page.tsx`는 페이지를 의미합니다.

### Q2: API는 `/api/` 아래에 모두 있나요?

**A**: 네. `/api/` 아래의 `route.ts` 파일이 모든 API 엔드포인트입니다.

### Q3: public 폴더의 파일은?

**A**: 브라우저가 직접 접근하는 정적 파일입니다.
- `/public/images/logo.png` → URL: `/images/logo.png`

### Q4: 여러 테마 (tech, icon, glass 등)는?

**A**: `/dashboard/[theme]/page.tsx` 형식으로 각각 다른 UI를 제공합니다.

## 🗂️ 폴더 구조 한눈에 보기

```
next-app의 역할 정리
│
├─ 사용자가 보는 부분 (프론트엔드)
│  └─ src/app/ & src/components/
│     (HTML, CSS, 인터렉션)
│
├─ 데이터 처리 부분 (백엔드)
│  ├─ src/app/api/
│  ├─ src/lib/
│  └─ src/models/
│  (데이터베이스, API 로직)
│
├─ 보안/권한 처리
│  └─ middleware.ts
│  (모든 요청 검사)
│
└─ 설정
   ├─ next.config.ts
   ├─ tsconfig.json
   └─ package.json
```

이 구조 덕분에 **프론트엔드와 백엔드를 한 폴더에서 관리**하면서도, 각각의 역할이 명확하게 분리되어 있습니다! 🎯
